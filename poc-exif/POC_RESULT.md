# PoC結果：EXIF自動旅程生成（2026-08-26）

検証した問い：**「写真を放り込むだけで旅程の骨格が自動で立ち上がるか」**
＝本事業の最大リスク「投稿負荷の高さ」を機械が肩代わりできるか。

## 判定：**成立（ただし逆ジオコーディングAPIの追加が必須条件）**

## ステップ1：EXIF抽出＋滞在クラスタリング → ✅ 成立
実写真162枚（iPhone/HEIC含む）で検証。

| 指標 | 実測 |
|---|---|
| 撮影時刻あり | 158/162（98%） |
| GPSあり | 132/162（81%） |

- 最適パラメータ：**時間ギャップ60分／移動距離800m**
  （初期値45分/300mは割れすぎて使い物にならなかった）
- **写真枚数が「盛り上がり」の代理指標として機能**。46枚/70枚＝メイン体験、1枚/12枚＝移動・立ち寄り。
  → 旅程の山場を投稿者に質問せずに推定できる。

## ステップ2：滞在クラスタ → 読める旅程ドラフト（Claude API） → ⚠️ 条件付き成立
ダミーデータ（京都1泊2日・11滞在）で検証。

**良かった点**
- 事実の捏造をしなかった（店名・食事・感想はすべて空欄のまま返した）
- GPS欠損クラスタを「判定不可」と正直に扱った
- 滞在時間×写真枚数からメイン/立ち寄りを正しく判定した

**問題点：座標→地名の精度が不足**

| 正解（ダミー設定） | LLM推定 | 判定 |
|---|---|---|
| 京都駅 | 京都駅周辺 | ✅ |
| 伏見稲荷大社 | 東福寺周辺 | ❌ 約1kmズレ |
| 錦市場 | 二条城／御所周辺 | ❌ ズレ |
| 清水寺 | 祇園・八坂周辺 | △ 惜しい |
| 先斗町 | 河原町・木屋町周辺 | ✅ |
| 嵐山 竹林 | 嵐山・嵯峨野周辺 | ✅ |
| 渡月橋 | 嵐山周辺 | ✅ |
| 金閣寺 | 金閣寺周辺 | ✅ |
| 祇園の宿 | 河原町・三条周辺 | △ ズレ |

→ 有名寺社は当てるが**1km級の誤りが出る**。「伏見稲荷に行ったのに東福寺と表示される」は
ユーザー体験として致命的（"魔法"が"バグ"に変わる）。

## 結論と次の必須アクション
**LLM単体の座標→地名推定では精度不足。逆ジオコーディングAPIが必須。**
- 候補：Google Places API（精度高・有料）／OSM Nominatim（無料・要利用規約確認）
- 設計：逆ジオコーディングで地名を確定 → LLMは「文章化・メイン判定」だけを担当
  （LLMに座標解決をさせないことが精度の鍵）

## その他の実装上の学び
- EXIF読込は162枚で約2分 → **サーバ側は非同期ジョブ必須**（工数見積りに反映要）
- HEIC（iPhone標準）対応に `pillow-heif` が必要
- パラメータ調整用のEXIFキャッシュを実装済み（`exif_cache.json`）
