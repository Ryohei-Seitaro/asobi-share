# feedback/backend-engineer.md — バックエンドエンジニアへのCEOフィードバック蓄積

CEOからのフィードバックのうち、バックエンドエンジニアの観点に関するものをここに記録する。
一定量たまった段階で、職種別エージェントの知見データとして外部化する候補になる。

## 2026-09-05
- 旅程内の場所（ロッカー等）・食事スポットからGoogleマップ／食べログへ遷移するための外部連携（Places API等）の検討が必要。
- チャット型の旅程提案機能（気分ヒアリング→レコメンド）のバックエンド設計が必要。
- 保存数→コイン付与・コイン残高管理・決済（現金/コイン選択）のデータモデル検討が必要。

## 2026-09-06
- 見つける画面のフィルタを人数・日数・国内海外にも対応させたいとの要望に伴い、tripsテーブルへ
  partySizeMin/partySizeMax/nights/internationalを追加するデータモデル変更が必要だった
  （既存のgenre文字列だけでは表現できなかったため）。

## 2026-09-06（追加・7件バッチ）
- 旅程を「日付ベース」で保存できるようにしたい。`trip_days.date_label`（表示用テキスト）ではなく
  実際の日付を持ち、開始日〜終了日から日数を自動算出。月・季節（何月に行ったか）でフィルタできるように。
  → tripsに startDate/endDate、季節や月の導出値を持たせるデータモデル変更が要る。
- ジャンルを「カテゴリ＞サブジャンル」の2階層に。既存の genre 文字列単体からの移行が必要。
- 「つくる」で人数・日数・国内/海外を入力必須にする（見つけるフィルタの前提データを確実に埋めるため）。
- 保存旅程のカレンダー連携を Google Calendar だけでなく TimeTree にも広げたい。日程指定して送る。
- 有料記事のコイン購入 server action は実装済み（tripPurchases / coinTransactions）だが、
  詳細画面でコイン購入UIに到達できない状態。paywall表示の出し分けを見直す。

## 2026-09-07
- 操作ごとにロードが走って遅い。時間がかかっている箇所を特定して高速化してほしい。
  - 特定した遅延要因：(1) `getOrCreateUser()` が毎レンダリングで `currentUser()`＝Clerk Backend API を1往復。
    (2) `neon-http` ドライバは1クエリ=1 HTTPSリクエストなのに、見つける画面は「users照会→一覧→保存ID→購入ID」を直列 `await` で4往復待ち。
  - 対応：`getOrCreateUser()` を `auth()`（セッションJWTのローカル読取、ネットワーク往復なし）ベースに変更。
    既存ユーザーは usersテーブルのPK参照1発のみ。行が無い初回だけ `currentUser()` にフォールバックして作成。
    読み取り専用ページ用に `getCurrentUserId()` を追加。見つける／マイページの独立クエリを `Promise.all` で並列化。
  - 学び：**Clerkは「ユーザーIDだけ要る」なら `auth()`、プロフィール本体が要るときだけ `currentUser()`**。
    `neon-http` で複数クエリを投げるときは必ず並列化（直列は往復回数ぶん線形に遅くなる）。
  - 後回し（データ増加時に対応）：trips の genre / start_date(month) / savesCount 等へのインデックス追加。現状シードが数十件で効果薄く、両者のDBに `drizzle-kit push` が要るため。

**記録タイミング：CEOのフィードバックが発生した瞬間に即時記録。**

## 2026-09-06
- タスク概要：メモ取り込み画面の写真枚数・サイズ制限、複数日パースの不具合、Googleカレンダーへの直接登録。
- 修正前の問題：写真が5枚・1MBまでしか載せられなかった（Server Actionsのデフォルトボディ上限が原因）。メモテキストの複数日程が1日にまとまってしまうパース不具合があった。Googleカレンダー連携が.icsのダウンロード/インポート止まりで手間だった。

- 傾向メモ：「一応動く」レベルでは満足せず、実際に使ってみて手間だと感じた導線（確認ステップが多い、手動操作が要る）はワンクリックまで踏み込んで改善を求める。技術的難易度（OAuth連携、外部API審査など）を先に説明すると、それを踏まえた上で本格対応を選ぶ傾向がある。

## 2026-09-06
- タスク概要：「見つける」から具体的な旅程を開くとNeon DBエラーが出る、との不具合報告。
- 修正前の問題：`src/db/schema.ts` に追加済みの `trip_events.map_url` / `tabelog_url`（Googleマップ/食べログURL入力機能で追加）が、CEO（Seitaro）の個人用Neon（asobi-share-dev）に反映されておらず、旅程詳細クエリが `column ... does not exist`（42703）で落ちていた。`.env.local` はgitignoreで共有されないため、各自がpull後に自分のNeonへ `db:push` する必要がある（既知の運用、`memory/20260906_web-local-verification.md`）。
- 対応：`npx dotenv -e .env.local -- drizzle-kit push` を実行。`db:push` スクリプト（`drizzle-kit push` のみ）は `.env.local` を自動ロードしないため、`DATABASE_URL` 未設定で `Either connection "url" ...` と失敗する。`dotenv-cli` は devDependency にあるので `dotenv -e .env.local --` を噛ませる。差分は nullable な2カラム追加のみで対話プロンプトなしで適用された。
- 傾向メモ：スキーマ変更を含む機能をpullしたら、動作確認の前に必ず自分のNeonへスキーマ反映する。`package.json` の `db:push` は env ロードが噛んでおらず単体で動かない点に注意（スクリプトを `dotenv -e .env.local -- drizzle-kit push` に直すか、README/CLAUDE.mdに手順を明記するのが望ましい）。
